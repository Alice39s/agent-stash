`@agent-stash/dsh-skill-scout` 是一个 DeepSeek Harness 插件。它在本机读取已经结束的会话，只根据工具结果判断任务是否成功，把在多个会话里重复成功的流程、失败后修复并通过检查的过程整理成 Skill 建议。建议要你看过证据、预览过草稿才会写入。文件在保存后没有被改过时，可以撤销写入。插件需要 DSH 0.2.1-rc.3 或更新的版本，收件箱与设置页在 DSH 的 Web 界面和桌面版里提供。

## 使用

- 标题栏图标：出现新的可保存建议时显示数量，打开收件箱后清零。没有新建议时只有图标，插件不弹通知。设置里「标题栏角标」选「只显示图标」时不显示数量。
- 收件箱：「可以保存」是复核过、带草稿的建议。「本地发现」是规则找到、还没复核成功的候选，包括复核中和复核失败的。已保存、已忽略和判定不值得保存的建议收在「历史」里。
- 详情的三页：「证据」列出每个来源任务的请求、命令、退出码和失败时的一行错误，「打开会话」跳回原会话。「Skill」是可以直接修改的草稿，「改动」是目标路径和文件 diff。
- 保存：新 Skill 默认写进项目的 `.agents/skills/<name>/SKILL.md`，也可以选用户级的 `~/.agents/skills`。复核认为已有 Skill 覆盖了这个任务时，建议只在原文件末尾追加一节。
- 撤销、忽略与恢复：保存后可以撤销。「忽略」把建议移到历史，「忽略类似建议」让相近的流程以后也不再提示，忽略的建议可以恢复。

## 判断规则

- 成功只看工具结果：最后一次修改之后，每条命令的最后一次运行都成功。Agent 在回复里说完成了不算，用户下一条消息表示结果不对时也不算。
- 重复流程要出现在至少 2 个独立会话里（可调）。从别的会话 fork 出来的历史不重复计数，同一会话里的反复重试不算重复。
- 失败恢复要有完整的链条：命令失败，接着安装依赖、改配置或换参数，然后同一个命令成功。只改业务代码的修复，要在多个会话里遇到同一个错误才提示。
- 通过检查、用到至少 6 条不同命令且跨 3 类以上命令的单个长任务，也会作为候选交给复核，卡片上标为「经验证的长任务」。
- 复核时附上最相关的已有 Skill，模型可以判为重复，或者给出改进。复核判定不值得保存后，证据增加到两倍才重新复核。

## 模型复核

后台复核默认关闭，关闭时也可以在详情里对单条发现点「用模型复核」。打开后，复核受每日次数、最小间隔和超时限制，一次只跑一个。复核模型不选时跟随 Agent 的默认模型。

发给模型的是脱敏后的证据：用户请求、工作目录、命令行、改动过的文件路径、退出码、每次失败的一行错误（「包含错误行」打开时）、Agent 最后一条回复的开头、用户的下一条消息，以及最多 3 个相关的已有 Skill 的名称和描述，其中最相关的一个附带 SKILL.md 正文摘录。完整的工具输出、工作区文件内容和 Agent 的思考过程不发送。证据超出字符上限时，先去掉 Agent 回复和 Skill 正文摘录。复核请求不带工具，也不在任何会话里运行。模型的回答要符合约定的结构，引用的证据都要存在，带命令的步骤里每一段命令都要在它引用的成功运行里出现过。含凭据、提示注入痕迹、下载后直接执行或删除根目录与主目录的草稿整条拒绝，sudo、强制推送、递归删除这类命令作为提醒显示在详情里。

## 数据

- 会话文本在存储、发送和显示之前先在本机脱敏：常见的 API Key、token、私钥、认证头、密码赋值、URL 里的账号密码和邮箱都换成占位符，macOS 与 Linux 的用户主目录（`/Users/<name>`、`/home/<name>`）换成 `~`。设置里可以追加正则规则。
- 插件只存 Episode 摘要、建议和最近两天的复核用量（次数与 token 数），放在 DSH storage domain `skill_scout` 里。超出历史范围的会话摘要会被删除，仍待处理的建议引用的除外。
- Agent 运行时插件不做分析：回合结束并空闲一段时间（默认 2 分钟）后才读取这个会话。
- 多个 DSH 实例共用同一个 DSH 目录时，只有一个实例在后台分析会话和自动复核。
- 写入只发生在你点保存之后，目标只能是项目或用户 Skill 目录下的 `<name>/SKILL.md`。新建时目标已有文件就不写入。追加到已有 Skill 时只在末尾加一节，预览之后文件被改过就不写入。
