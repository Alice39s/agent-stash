`@agent-stash/dsh-skill-scout` is a DeepSeek Harness plugin. It reads finished sessions on your machine, judges whether a task succeeded only from tool results, and turns workflows that succeeded in several sessions, and fixes that passed a check after a failure, into Skill suggestions. Nothing is written until you have looked at the evidence and previewed the draft, and you can undo a write as long as the file has not changed since. The plugin needs DSH 0.2.1-rc.3 or later. The inbox and settings are in the DSH web interface and the desktop app.

## Usage

- Title bar icon: shows a count when new suggestions are ready to save, and the count clears when you open the inbox. Without new suggestions it is only an icon, and the plugin shows no notifications. Set Header badge to Icon only to hide the count.
- Inbox: Ready to save holds reviewed suggestions with a draft. Found locally holds candidates that the rules found and no review has accepted yet, including ones under review and ones whose review failed. Saved, dismissed, and not-worth-saving suggestions move to History.
- Detail tabs: Evidence lists each source task's request, commands, exit codes, and one error line per failure, and Open session goes back to the session. Skill is the draft, which you can edit. Changes shows the target path and the file diff.
- Save: a new Skill goes to the project's `.agents/skills/<name>/SKILL.md` by default, or to `~/.agents/skills` for your user. When the review finds that an existing Skill covers the task, the suggestion only appends a section to the end of that file.
- Undo, dismiss, and restore: you can undo a save. Dismiss moves a suggestion to History, and Dismiss similar also stops close variants from coming back. Dismissed suggestions can be restored.

## Rules

- Success comes only from tool results: after the last edit, the last run of every command succeeded. The agent saying it is done does not count, and neither does a task the user says is wrong in the next message.
- A repeated workflow must appear in at least 2 independent sessions (configurable). History inherited by a fork counts once, and retries inside one session do not count as repeats.
- A recovery needs the whole chain: a command fails, then dependencies are installed, configuration changes, or arguments change, and then the same command succeeds. A fix that only edits application code is suggested only when the same error shows up in several sessions.
- A single long task that passed a check and used at least 6 distinct commands from 3 or more command families also goes to review as a candidate, labeled Long verified task.
- The review sees the most related existing Skill and can call the candidate a duplicate or propose an improvement. After the review says a candidate is not worth saving, it is reviewed again only when the evidence doubles.

Background review is off by default. With it off, you can still click Review with model on a single finding in its detail. With it on, reviews are limited by a daily count, a minimum interval, and a timeout, and only one runs at a time. Without a chosen review model, the review uses the agent's default model.

The model receives redacted evidence: user requests, the working directory, command lines, paths of edited files, exit codes, one error line per failure (when Include error lines is on), the start of the agent's last reply, the user's next message, and the names and descriptions of up to 3 related existing Skills, with an excerpt of the most related SKILL.md. Full tool output, workspace file contents, and the agent's reasoning are not sent. When the evidence exceeds the character limit, the agent reply and the Skill excerpt are dropped first. The review request has no tools and runs outside any session. The answer must match the expected structure, and every cited piece of evidence must exist. Every command in a step, including each part of a command chain, must appear in a successful run that the step cites. A draft that contains a credential, signs of prompt injection, a download piped into a shell, or a delete of the root or home directory is rejected. Commands such as sudo, force pushes, and recursive deletes are shown as cautions in the detail.

## Data

- Session text is redacted on your machine before it is stored, sent, or shown: common API keys, tokens, private keys, auth headers, password assignments, credentials in URLs, and email addresses become placeholders, and home directories on macOS and Linux (`/Users/<name>`, `/home/<name>`) become `~`. You can add regular expressions in the settings.
- The plugin stores only episode summaries, suggestions, and review usage for the last two days (counts and tokens), in the DSH storage domain `skill_scout`. Summaries of sessions past the history range are deleted unless a pending suggestion cites them.
- The plugin does no analysis while the agent runs. It reads a session after a turn ends and the session stays idle for a while (2 minutes by default).
- When several DSH instances share one DSH home directory, only one of them analyzes sessions and runs background reviews.
- Writes happen only after you click Save, and only to `<name>/SKILL.md` under a project or user Skill directory. A new Skill is not written when a file already exists at the path. Adding to an existing Skill only appends a section to the end of the file, and nothing is written if the file changed after the preview.

## Install

<Tabs items={['Plugin market', 'Desktop app', 'Command line']}>
<Tab value="Plugin market">

Add the index source as described in [Import the Agent Stash plugin market](../install.mdx#import-the-agent-stash-plugin-market), then install `@agent-stash/dsh-skill-scout` from the Discover page.

</Tab>
<Tab value="Desktop app">

On the Plugins page, click Add plugin and enter `@agent-stash/dsh-skill-scout`.

</Tab>

```bash
dsh plugin --profile web add @agent-stash/dsh-skill-scout
```

</Tab>
</Tabs>
