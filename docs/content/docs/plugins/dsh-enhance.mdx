## 预设

| 预设             | 图标 | 改写方式                                                                                                                                                                                                                                                                                                                                                                  |
| ---------------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 润色 Prompt      | 星光 | 先按「仅结构化整理」的步骤整理，再在原意内补全：写明目标、范围、预期结果与检查方式，请 AI 比较几种做法并推荐一种，缺的信息让 AI 先说明假设。补写的每一句都要能追溯到草稿、会话上下文或适用的通用工程做法（例如先测量再优化），不编造文件、接口、数字和决定。措辞按下面三份写作指南去掉 AI 腔，语气跟随草稿。篇幅不超过原稿的 3 倍，也不超过约 500 个汉字或 250 个英文单词 |
| 仅结构化整理     | 列表 | 主要要求放在最前，其余按背景、要求、约束分组，并列的几项改成列表，保留原有措辞，不增删要点                                                                                                                                                                                                                                                                                |
| 使 Prompt 更精炼 | 压缩 | 去掉口头语、重复和说错又改口的部分，只留最终的要求、约束与问题，适合整理语音输入，结果比原稿短                                                                                                                                                                                                                                                                            |

三种预设共用一组规则：改写结果与草稿使用同一种语言，代码、命令、路径、链接与反引号里的内容原样保留。草稿是一个问题时，改写后仍是问题，不回答它。草稿已经清楚时返回原稿，按钮左侧提示「已经很清楚，无需改动」，几秒后消失。

共用规则与每个预设的指令都按 `<role>`、`<rules>`、`<mode>` 这类标签分节，在配置页可以直接查看和修改。

### 写作指南

润色 Prompt 的指令内联了三份写作指南的全文，改写器把其中的模式清单用在自己补写和改动的句子上。指南里的工作流程、输出格式和向用户提问的要求不适用，返回什么仍由共用规则决定。

| 指南                                                          | 内容                                                        |
| ------------------------------------------------------------- | ----------------------------------------------------------- |
| [humanizer](https://github.com/blader/humanizer)              | 按 Wikipedia「Signs of AI writing」整理的 AI 写作模式与改法 |
| [no-ai-slop](https://github.com/petergyang/no-ai-slop)        | 保留作者语气、删去套话与空洞强调的编辑规则                  |
| [no-negative-echo](https://github.com/LB623/no-negative-echo) | 只写最终采用的内容，会话里被否决或改口的说法不进入结果      |

三份指南都是 MIT 许可，原样随包放在 `vendor/` 里，`vendor/manifest.json` 记录每份的上游仓库与提交。仓库的同步任务每天检查上游，有更新时开 PR 并自动合并。

润色预设内联三份指南，输入比另外两个预设更多；菜单顶部按 o200k_base 编码显示各预设的输入估算。

自定义预设的指令也可以写 `<include ref="humanizer" />` 引用这些指南，可用的名称是 `humanizer`、`no-ai-slop` 和 `no-negative-echo`。Host 发出请求前把它换成指南全文；名称不存在时改写失败，把指针移到失败说明上可以看到可用的名称。

## 使用

- 草稿为空时按钮不显示。把指针移到按钮上，提示写着「点我增强提示词」，关联了会话上下文时注明轮数。点按钮打开预设菜单，数字键 <Kbd>1</Kbd>–<Kbd>9</Kbd> 直接选择对应的预设。
- 菜单顶部显示 o200k_base 输入估算和关联的上下文轮数。数字按指针或键盘焦点所在的预设计算，没有指向预设时按第一个预设。
- 改写进行中，草稿锁定、不能编辑，按钮变成停止按钮。点它或按 <Kbd>Esc</Kbd> 停止，草稿保持原样。
- 改写完成后，按钮左侧出现撤销按钮，点它回到原稿。连续用几个预设改写时，撤销回到最早那份草稿。改动草稿或发送后，撤销按钮消失。
- 失败原因显示在按钮左侧，草稿不变。模型报错、结果被检查拒绝、预设的指令无法使用、随包分发的写作参考读不出来、读取会话失败和无法连接 DSH 时，把指针移到说明上可以看到具体原因。
- 草稿里有文件或会话的引用块时按钮不可用：改写会把引用块变成纯文本。

改写结果要通过以下检查才会写回输入框：

- 不以「以下是」「好的」「Here is」这类回答式开头。
- 与草稿使用同一种文字（中日韩文字或拉丁字母）。
- 草稿里的代码块、行内代码、链接和凭据占位符全部保留。

预计用量使用 [tiktoken](https://github.com/dqbd/tiktoken) 的 `o200k_base` 编码器，分别编码系统提示、会话上下文与草稿后相加。它只是输入文本估算，不是所选模型的 tokenizer 或计费结果；分段边界、协议开销、输出和推理均可能使实际用量不同。实际用量以模型返回为准。

## 会话上下文

开启「附带最近几轮对话」（默认开启）时，改写请求带上当前会话最近的几轮对话（默认 3 轮，最多 10 轮），让改写器理解「这个」「刚才的方案」指的是什么。有上下文时，按钮的提示和菜单顶部写着「已关联最近 N 轮上下文」。

- 只发送用户消息的正文、助手回复的正文和压缩后的会话摘要。工具调用、工具输出、推理过程和系统注入的消息都不发送。
- 超过 12 行的代码块只保留前 6 行。每条用户消息最多 1200 个字符，每轮的助手回复加起来最多 1200 个字符，摘要最多 1500 个字符，合计超过 4000 个字符时从最早的一轮开始丢弃。
- 上下文里能识别出的 API key、令牌、私钥，以及地址里的密码，替换为 `[redacted]`。草稿里的这类内容以 `⟦secret-1⟧` 这样的占位符发给模型，结果写回输入框前换回原文。

## 配置项

在插件页打开「增强提示词」的详情，点「配置」。菜单底部的「管理预设…」也会打开这个详情页。改动点「保存」后生效。

| 配置项           | 字段                | 可选值                                                                                                                      | 默认     |
| ---------------- | ------------------- | --------------------------------------------------------------------------------------------------------------------------- | -------- |
| 模型             | `provider`、`model` | 留空时跟随会话，使用当前对话下一次请求会用的模型与推理强度，会话还没选过模型时用 DSH 的默认模型。也可以从模型列表里指定一个 | 跟随会话 |
| 推理强度         | `effort`            | 指定的模型支持推理强度时出现，留空用模型的默认档位                                                                          | 模型默认 |
| 超时（秒）       | `timeout`           | 5–600，超时后按钮左侧提示「N 秒内没有结果」                                                                                 | 60       |
| 附带最近几轮对话 | `context`           | 见[会话上下文](#会话上下文)                                                                                                 | 开启     |
| 附带轮数         | `contextTurns`      | 1–10                                                                                                                        | 3        |
| 快捷键           | `shortcut`          | 开启后按它打开菜单，改写进行中按它停止，完成后按它撤销                                                                      | 关闭     |
| 预设             | `presets`           | 调整顺序、删除，修改图标、名称、说明与改写指令，或添加自定义预设                                                            | 三个内置 |

快捷键开启后，macOS 上默认绑定 <Keys keys={['⇧', '⌘', 'E']} />，其他系统为 Ctrl+Shift+E。浏览器里的 Linux 只放行少数组合键，那里没有默认按键。默认按键与其他命令冲突时也不绑定。这两种情况都可以在 DSH 的「快捷键」设置页自行指定。

也可以在 profile 的 patch 里写。`presets` 整体替换预设列表，内置预设只写 `id` 即可沿用内置的名称、说明与指令：

```yaml title="cordis.patch.yml"
- id: dsh-enhance
  name: "@agent-stash/dsh-enhance"
  config:
    timeout: 30
    shortcut: true
    presets:
      - id: concise
      - id: structure
      - id: steps
        title: 拆成步骤
        description: 按执行顺序列出要做的事
        icon: checklist-outline
        prompt: Rewrite the draft as a numbered list of the steps it asks for, in the order they should be done.
```

自定义指令接在内置的共用规则之后，改写结果仍要通过上面的检查。

`icon` 取 DSH 图标库里的图标名，留空时用默认图标，写了不在下面范围里的名称也用默认图标：`sparkle`、`enhance-outline`、`flat-list-outline`、`list-pen-outline`、`checklist-outline`、`compact-outline`、`wrap-lines-outline`、`edit-outline`、`microphone-outline`、`think-outline`、`light-outline`、`goal-outline`、`plan-outline`、`question-outline`、`info-outline`、`search-outline`、`inspect-outline`、`compare-split-outline`、`code-outline`、`api-outline`、`database-outline`、`branch-outline`、`warning-triangle-outline`、`shield-outline`、`gauge-outline`、`clock-outline`、`link-outline`、`globe-outline`、`user-outline`、`users-outline`、`skill-outline`、`agent-preset-outline`、`personalization-outline`、`deliver-doc`、`folder-open-outline`、`paper-plane-outline`。

插件的 Host 半部注册三条路由：`GET /dsh-enhance/context` 返回下一次改写会附带的轮数，以及每个预设在草稿为空时的预计输入 token 数；`POST /dsh-enhance/tokens` 估算草稿的 o200k_base token 数；`POST /dsh-enhance/rewrite` 读取会话、调用模型并检查结果。路由都经过 DSH 的连接校验，草稿最多 20000 个字符。菜单打开时，草稿估算防抖 150 ms，关闭或编辑后取消旧请求。编码器留在 Host，首次需要时创建并复用，插件卸载时释放；浏览器不加载 WASM。

需要 DSH 0.2.1-rc.3 或更新的版本。
