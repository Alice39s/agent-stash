## 预设

| 预设             | 改写方式                                                                                                          |
| ---------------- | ----------------------------------------------------------------------------------------------------------------- |
| 润色 Prompt      | 写明目标、范围、预期结果与检查方式，请 AI 比较几种做法并推荐一种；缺的信息让 AI 先说明假设。篇幅不超过原稿的 3 倍 |
| 仅结构化整理     | 主要要求放在最前，其余按背景、要求、约束分组，并列的几项改成列表；保留原有措辞，不增删要点                        |
| 使 Prompt 更精炼 | 去掉口头语、重复和说错又改口的部分，只留最终的要求、约束与问题，适合整理语音输入；结果比原稿短                    |

三种预设共用一组规则：改写结果与草稿使用同一种语言；代码、命令、路径、链接与反引号里的内容原样保留；草稿是一个问题时改写后仍是问题，不回答它；草稿已经清楚时返回原稿，按钮左侧提示「已经很清楚，无需改动」。

## 使用

- 草稿为空时按钮不显示。点按钮打开预设菜单，数字键 <Kbd>1</Kbd>–<Kbd>9</Kbd> 直接选择对应的预设。
- 改写进行中，草稿锁定、不能编辑，按钮变成停止按钮；点它或按 <Kbd>Esc</Kbd> 停止，草稿保持原样。
- 改写完成后，按钮左侧出现撤销按钮，点它回到原稿。连续用几个预设改写时，撤销回到最早那份草稿。改动草稿或发送后，撤销按钮消失。
- 失败原因显示在按钮左侧，草稿不变。模型报错与结果被检查拒绝时，把指针移到说明上可以看到具体原因。
- 草稿里有文件或会话的引用块时按钮不可用：改写会把引用块变成纯文本。

改写结果要通过以下检查才会写回输入框：不以「以下是」「好的」「Here is」这类回答式开头；与草稿使用同一种文字（中日韩文字或拉丁字母）；草稿里的代码块、行内代码、链接和凭据占位符全部保留。

## 会话上下文

开启「附带最近几轮对话」（默认开启）时，改写请求带上当前会话最近的几轮对话（默认 3 轮，最多 10 轮），让改写器理解「这个」「刚才的方案」指的是什么。有上下文时，按钮的提示和菜单顶部写着「已关联前 N 轮上下文」。

- 只发送用户消息的正文、助手回复的正文和压缩后的会话摘要。工具调用、工具输出、推理过程和系统注入的消息都不发送。
- 超过 12 行的代码块只保留前 6 行。每条用户消息与助手回复最多 1200 个字符，摘要最多 1500 个字符，合计超过 4000 个字符时从最早的一轮开始丢弃。
- 上下文里能识别出的 API key、令牌、私钥和带密码的地址替换为 `[redacted]`。草稿里的这类内容以 `⟦secret-1⟧` 这样的占位符发给模型，结果写回输入框前换回原文。

## 配置项

在插件页打开「增强提示词」的详情，点「配置」；菜单底部的「管理预设…」也会打开这个详情页。改动点「保存」后生效。

| 配置项           | 字段                | 可选值                                                                                 | 默认     |
| ---------------- | ------------------- | -------------------------------------------------------------------------------------- | -------- |
| 模型             | `provider`、`model` | 留空时跟随会话，使用当前对话下一次请求会用的模型与推理强度；也可以从模型列表里指定一个 | 跟随会话 |
| 推理强度         | `effort`            | 指定的模型支持推理强度时出现，留空用模型的默认档位                                     | 模型默认 |
| 超时（秒）       | `timeout`           | 5–600，超时后按钮左侧提示「N 秒内没有结果」                                            | 60       |
| 附带最近几轮对话 | `context`           | 见[会话上下文](#会话上下文)                                                            | 开启     |
| 附带轮数         | `contextTurns`      | 1–10                                                                                   | 3        |
| 快捷键           | `shortcut`          | 开启后打开菜单；改写进行中按它停止，完成后按它撤销                                     | 关闭     |
| 预设             | `presets`           | 调整顺序、删除，修改名称、说明与改写指令，或添加自定义预设                             | 三个内置 |

内置预设的改写指令留空时使用内置指令，「恢复内置」清空自己填写的名称、说明和指令。自定义预设必须填写改写指令才能保存。

快捷键开启后默认绑定 <Keys keys={['⇧', '⌘', 'E']} />，其他系统为 Ctrl+Shift+E。浏览器里的 Linux 只放行少数组合键，那里没有默认按键；默认按键与其他命令冲突时也不绑定。这两种情况都可以在 DSH 的「快捷键」设置页自行指定。

也可以在 profile 的 patch 里写。`presets` 整体替换预设列表，内置预设只写 `id` 即可沿用内置的名称、说明与指令：

```yaml title="cordis.patch.yml"
- id: dsh-enhance
  name: "@agent-stash/dsh-enhance"
  config:
    timeout: 30
    shortcut: true
    presets:
      - id: concise
      - id: structure
      - id: steps
        title: 拆成步骤
        description: 按执行顺序列出要做的事
        prompt: Rewrite the draft as a numbered list of the steps it asks for, in the order they should be done.
```

自定义指令接在内置的共用规则之后，共用规则优先：同一种语言、原样保留技术内容和只改写不回答这几条，自定义指令改变不了。

插件的 Host 半部注册两条路由：`GET /dsh-enhance/context` 返回下一次改写会附带的轮数，`POST /dsh-enhance/rewrite` 读取会话、调用模型并检查结果。两条路由都经过 DSH 的连接校验，草稿最多 20000 个字符。

## 安装

需要 DSH 0.2.1-rc.3 或更新的版本。

<Tabs items={['插件市场', '桌面版', '命令行']}>
<Tab value="插件市场">

按[导入 Agent Stash 插件市场](../install.mdx#导入-agent-stash-插件市场)的步骤添加索引源，然后在「发现」页安装 `@agent-stash/dsh-enhance`。

</Tab>
<Tab value="桌面版">

在「插件」页点「添加插件」，填入 `@agent-stash/dsh-enhance`。

</Tab>
<Tab value="命令行">

```bash
dsh plugin --profile web add @agent-stash/dsh-enhance
```

</Tab>
</Tabs>
