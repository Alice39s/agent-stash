## @agent-stash/dsh-skill-scout@0.3.1

### 插件简介

插件列表里的简介改为一句话：

- /init：用其他 Coding Agent 的 /init 预设分析项目，写出 AGENTS.md
- Prompt 回溯：按 ↑↓ 翻看当前会话发过的 Prompt
- Prompt 自动补全：用所有会话的历史 Prompt 补全输入内容
- 提示词增强器：一键润色、结构化、提炼 Prompt 草稿的核心内容
- Agent Stash 基础核心框架：统一设置 Agent Stash 插件的面板、补全灰字与动画
- 消息编辑：编辑消息、重新生成回复或重试回合，改动另存为可切换的版本
- 经验提炼器：从已结束的会话里提炼可复用的流程，审核后存为 Skill

### 插件名称

插件页里显示的中文名称：

- `@agent-stash/dsh-autosuggest`：Prompt 自动补全
- `@agent-stash/dsh-enhance`：提示词增强器
- `@agent-stash/dsh-stash-kit`：Agent Stash 基础核心框架
- `@agent-stash/dsh-skill-scout`：经验提炼器，找不到发现模型和无法修改 Skill 的提示里也用这个名称

## @agent-stash/dsh-skill-scout@0.3.0

### 经验提炼：会话 Tab、历史回溯提炼与多个 idea

- 每个会话多了「经验提炼」Tab，和对话、轨迹并列：顶部是本会话的分析状态，可以立即分析或把整段会话交给发现模型提炼；左栏按「待你决定」「本地发现」「历史」分组列出引用本会话的 idea，下面是本会话的任务；右栏直接显示方案、草稿编辑、改动和证据。详情不再用弹窗。视图较窄时只显示一栏。
- 列表每行前的圆点标出状态。详情顶部标出这一条所在的步骤（发现、摘要、草稿、保存）和下一步要做什么；同一线索的多个 idea 用「‹ n/m ›」切换；保存位置（项目或用户）并进保存按钮的下拉，「忽略类似建议」收进「更多操作」。
- 侧栏新增「历史回溯提炼」页，分「建议」「搜索」「统计」三栏。标题栏的收件箱保留，点卡片会打开这个页面并选中这条建议。
- 搜索在插件保存的脱敏任务记录里查找请求、命令、错误行、文件路径和任务中的插话，勾选 1 到 12 个任务可以交给发现模型提炼。「回溯 90 天」「回溯全部」在后台逐个读入历史范围之外的会话，显示进度，可以暂停。
- 统计页顶部是四个总数（已分析的会话、近 30 天的任务、待你决定的 idea、已保存的 Skill），下面是近 30 天每天按结果堆叠的任务图、线索与 idea 的状态占比、跨会话的高频动作（带 8 周走势）与反复出现的错误、每天的新线索、分析失败的会话、近 7 天的模型用量（输入含缓存读写），以及最近模型调用的表格。图表支持键盘查看提示和隐藏某一类。
- 一条线索的摘要可以给出多个互不重叠的 idea：规则发现的线索最多 3 个，提炼本会话或所选任务最多 5 个。每个 idea 单独同意、生成、保存或忽略；不同线索里同名的 idea 合成一张卡片，「忽略类似」也会屏蔽之后出现的相近 idea。
- 模型请求按真实阶段显示进度：排队、准备证据、等待响应、思考、生成（已收到的字数）、核对证据，并显示已用时间；占位条随收到的内容逐条点亮。请求结束后结论留在原处；这一条没有列在打开的会话 Tab、「建议」栏或浮层里时，才弹出带「查看」的提示。
- 摘要请求带上证据会话能看到的全部 Skill 名称（最多 200 个），模型据此避开已经占用的名称，覆盖已有 Skill 的流程改为追加内容。
- 命令解析：多行脚本按行拆成命令；here-document 与 here-string 的内容、注释、`for`/`if`/`case` 等 shell 结构和 `set`/`export` 等内建命令不再被当成命令；含 `${…}`、`$((…))` 的命令不再让整个会话分析失败。分析失败的会话会记录原因，日志没有变长就不再重试。

### 升级说明

- 插件存储升级到新格式。升级后历史范围内的会话按新规则重新分析，建议重新生成；0.2 版写入的 Skill 文件留在原处，但不能再从插件里撤销。

## @agent-stash/dsh-skill-scout@0.2.0

### 经验提炼：先给摘要，同意后再生成 Skill

- 模型分两步参与。发现模型先给每个候选写一份几行的方案：发现了什么、Skill 的用途、何时使用、要新建或追加到哪个 Skill、步骤提纲、风险和验证方式。你在详情里点「生成 Skill 草稿」之后，生成模型才按这份摘要写完整的 Skill；后台从不生成草稿。
- 设置页分成「摘要」与「生成 Skill」两组，发现模型与生成模型各自选择模型、推理强度和超时，不选时都跟随 Agent 的默认模型。「后台生成摘要」默认关闭；每日次数与间隔只限制后台摘要，手动发起的请求不计入。
- 收件箱的「待你决定」分组列出等你同意的摘要和可以保存的草稿，卡片上显示摘要里的用途说明，标题栏数字也只数这两类。详情新增「摘要」页；草稿生成期间，「Skill」页显示按 SKILL.md 排版的占位条，系统设置了减少动态效果时占位条静止。
- 命令按动作比较：`pnpm build` 与 `npm run build`、`npx vitest` 与 `pnpm exec vitest`、`bash scripts/release.sh` 与 `./scripts/release.sh`、`git checkout -b` 与 `git switch -c`、`turbo run build` 与 `pnpm build` 这类写法算同一步；`tsx`、`ts-node` 运行的脚本按文件名比较，`bash -c` 里的命令按里面的命令算。其他 Agent 与 MCP 服务器的改文件、执行命令类工具按名字归类。
- 重复流程的相似度按动作加权计算：`build` 与 `build:web` 这类同前缀脚本算部分相同，提交、推送、装依赖这类日常步骤权重低，两个任务至少要共有一个有区分度的步骤，共有步骤的顺序要大体一致。用不同语言描述的同一流程，共有两个以上有区分度的步骤时也会归为一组。
- 失败恢复按动作闭合：`npm test` 失败、装好依赖后 `pnpm test` 通过也算一条恢复链。重跑时改了选项或环境变量（`pnpm test --runInBand`）算修复，只换文件、参数或选项的值不算。跨会话比较错误时，路径、版本号与平台名（`darwin-arm64`、`linux-x64-gnu`）先换成占位符。
- 草稿只写摘要指定的那个 Skill；你在任务进行中插入的消息（每个任务最后 3 条）随证据发给模型，纠正和命令失败的原因写成前置条件、注意事项或限制。证据会话能看到名为 `skill-creator` 的 Skill 时，草稿请求带上它的 SKILL.md（脱敏后取前 20000 字符）作为写作指南，按 DSH 加载技能的格式附上，请求因此更长；摘要请求不带。
- 草稿里的命令可以和引用的运行写法不同，动作相同、并且这个动作在证据里成功过即可通过证据核对；复现失败的步骤可以引用那次失败。
- 内联代码（`python -c`、`node -e`）、HTTP 请求（`curl`、`wget`）和远程登录（`ssh`）从动作上看不出做了什么，在流程比较里和日常步骤一样权重低：只共有这类命令的两个任务不会归为重复流程，换一段内联代码或换一个 URL 再试也不算失败恢复。

### 升级说明

- 插件存储升级到新格式。升级后历史范围内的会话按新规则重新分析，建议重新生成；0.1 版写入的 Skill 文件留在原处，但不能再从收件箱撤销。
- 0.1 版的「后台复核」开关、复核模型、推理强度、超时、每日复核次数与复核间隔不再读取。需要后台摘要时，在设置页重新打开「后台生成摘要」，并在「摘要」与「生成 Skill」两组里选择模型。

## @agent-stash/dsh-skill-scout@0.1.0

### 新增 DSH 插件「经验提炼」

- `@agent-stash/dsh-skill-scout`：在本机读取已经结束的会话，把在多个会话里重复成功的流程、失败后修复并通过检查的过程整理成 Skill 建议。成功只看工具结果，Agent 自己说完成不算；fork 继承的历史不重复计数。
- 会话标题栏右侧的 Skill 图标在有新的可保存建议时显示数量。收件箱分「可以保存」「本地发现」「历史」三组；详情里可以查看每个来源任务的命令、退出码和错误行，预览并修改 Skill 草稿，查看写入的文件 diff。
- 保存后写入项目的 `.agents/skills/<name>/SKILL.md` 或用户的 `~/.agents/skills`，并确认 DSH 的 Skill 列表里出现了它；保存可以撤销。改进已有 Skill 时只在文件末尾追加一节。忽略与「忽略类似建议」可以恢复。
- 模型复核默认关闭。打开后把脱敏后的证据发给所选模型（默认跟随 Agent 的默认模型），受每日次数、间隔与超时限制；回答要通过结构、证据引用和凭据检查才会成为建议。
- 在「插件」页的配置页设置历史范围、静默期、重复次数、复核模型与推理强度、超时、限额、错误行与追加的脱敏规则、标题栏角标和默认保存位置。
- 需要 DSH 0.2.1-rc.3 或更新版本的 Web 界面或桌面版，在「插件」页填入 npm 包名即可安装。
